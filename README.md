# HELIO-FORGE — Mission Control

An educational Earth-observing mission design game with an interactive Solar System and Milky Way explorer. The mission game uses illustrative parameters and is not a flight-design tool. The explorer remains incomplete and is not a precision universe simulator.

## Run and configure

Requires Node.js 20 or later.

```sh
npm install
cp .env.example .env
# Add NASA_API_KEY to .env on the server (do not commit it)
npm run dev
```

For production, run `npm run build` and `npm start`; Express serves the app and `/api` on `PORT` (default 3001). Set `NASA_API_KEY` as a **server-side environment variable** in your deployment environment. Never use a `VITE_` prefix or place the key in client code. The supplied key is not in the repository; `.env` is ignored by Git.

APOD, today's NEO feed, and today's DONKI solar flare data use NASA Open APIs and require that key. The JPL Small-Body Database (SBDB) and Horizons endpoints do not require a NASA key. All requests go through the server with one-hour bounded in-memory caching, timeout, input validation and error handling. The server needs outbound access to `api.nasa.gov`, `ssd-api.jpl.nasa.gov`, `ssd.jpl.nasa.gov` and `exoplanetarchive.ipac.caltech.edu`; where these are blocked, the interface reports the failure rather than inventing results. NASA media may have separate credits and usage restrictions.

## Vercel deployment

`vercel.json` builds the Vite frontend, and `api/[...path].js` exposes the same validated Express API routes as a Vercel Node function. Set `NASA_API_KEY` in the project's server-side environment for APOD, NEO and DONKI; the exoplanet, Horizons and SBDB routes do not use that key. Caches are bounded but in-memory per function instance, not shared or durable. Outbound NASA/JPL service availability and any deployment protection still apply. Local handler tests use mocked/error paths; a new Vercel deployment and live NASA/JPL calls must be tested in the target environment before declaring them operational. Never expose or commit the key.

## Mission and exploration flow

Mission Lab opens with visible entry points to both the design game and the Solar System explorer. Exploring and returning to Mission Lab preserves the current mission stage, in-flight decisions and report while the page remains open; those flight states are **not** persisted after a refresh. The current design autosaves locally where storage is available, and the builder reports when it cannot save. The optional named library and share link contain a design, not decisions or reports. Reset asks for confirmation. From Earth’s profile in Explore, an explicit, confirmed handoff selects one Earth science objective in Mission Lab; it keeps component choices but resets the current flight decisions and report. It is a question handoff, not data collected from the 3D view.

Three fictional campaign conditions (standard, repeating cloud-limited observations and intermittent downlink) let the same design be tested under different rules. Their effects are assumptions, not measured weather or probabilities. A third in-flight choice at month 10 trades an assumed 40% extra contact capacity against a 65% science-duty cap for that month. Version 2 share links and the local library include campaign conditions; older version 1 links and saved designs default to the standard campaign. A downloaded report includes the scenario, all three choices and the monthly log.

A science recommendation can explicitly apply the objective's modeled instrument and orbit without changing the rest of the design. The builder shows a first-month model estimate, a preflight checklist with links to relevant subsystems, and launch-hold recovery links. The preflight estimate is not a flight forecast. Re-selecting the current choice does not discard an existing flight. In the 3D assembly view the bus, instrument, power and communications fields highlight their corresponding conceptual geometry; the other subsystem fields do not imply a visible 3D representation. All spacecraft geometry and highlighting remain illustrative.

## Canvas-first exploration

Solar System and galaxy exploration open with the simulator unobstructed. Use **Objects** or **Catalogue** to search and select, and **Details** to open the selected object's profile. The Solar System's **Planets** control expands a quick-selection strip; the time bar, camera controls and galaxy shortcut stay available. The exoplanet system's **Planets & data** button opens its archive and planet list. Close each panel with its close button; Escape closes Solar System and galaxy drawers, and Ctrl/Cmd+K opens catalogue search. The **Guide** control explains the primary tools and limitations; on narrow screens Solar System speed and date controls are in the **Time** panel, and the exoplanet time bar can scroll horizontally. Cinematic mode still provides a distraction-free view.

## Exploring without WebGL

If WebGL cannot start or its context is lost, the Solar System, Milky Way and curated exoplanet views automatically switch to interactive **2D maps**. You can also enable *Lightweight 2D mode* in Solar System display settings or the galaxy catalogue, or use **TRY 3D** to retry WebGL. Selection through the existing catalogues, drag-to-pan, wheel/pinch zoom, keyboard/button zoom, reset and navigation between views continue to work. Mission Lab still uses its separate schematic fallback if WebGL is unavailable. A modern browser with JavaScript and SVG is required; the 2D path is not a guarantee for every device or browser.

The Solar System overview projects the existing approximate planetary model at 12:00 UTC on the selected day; distances are compressed and sizes are symbolic. Other catalogue objects open static illustrative portraits and are not placed on that overview. A software Canvas 2D orthographic projection is used for textured portraits when available; a simple clipped image remains if Canvas 2D fails. These portraits are not current images, trajectories or physically scaled views. The galaxy overview uses 2,400 procedural illustrative points, not observed galactic stars or dust. Its local view is a flattened x/z projection of an incomplete HYG subset, and optionally a sampled maximum of 4,000 of the 1,000,000 Gaia sources; vertical depth is omitted. All Gaia caveats and ID search continue to apply. Deep-sky points are approximate, symbolic Hubble pointings. The six exoplanet systems use the same measured semi-major-axis selection, arbitrary phases and compressed orbit spacing as the 3D schematic; neither mode is an ephemeris. Physical-scale, cinematic glow, atmosphere, sky and 3D quality settings do not apply to the 2D map; orbit and label toggles do. Zoom handoffs switch views rather than depicting a continuous physical journey.

### Individual object artwork

Every selectable HYG or searched Gaia star has a deterministic procedural portrait in its profile and a larger illustrative graphic when selected on the map; HYG catalogue and neighbor lists also have individual icons. Broad stellar colors use the available HYG B−V or Gaia BP−RP color band; a neutral palette is used if the index is missing. Texture, surface details and size are artistic inventions, not observations or measured properties. Only a subset of catalogue points is displayed in 2D, and the optional million-source Gaia layer remains sampled/adaptive for performance; distant and unselected objects can still appear as points. The curated exoplanet lists and selected profiles have seeded planet artwork, with seeded banded, cratered or marbled illustrative graphics in both 2D and 3D. The pattern is a decorative choice, not an inferred planet type. Exoplanet colors, textures and sizes are invented and do not imply composition, weather, habitability or an observed surface. Known Solar System objects retain their existing illustrations or symbolic portraits; deep-sky images, when present, are credited observations. Only the existing six curated exoplanet systems are available, and not every object in the actual solar neighborhood is in these catalogues.

## Explorer resilience and loading

The Solar System, physical-scale view and Galaxy Explorer load only when opened, keeping their code out of the initial Mission Lab bundle. The mission spacecraft scene and shared Three.js bundle now load on demand when a 3D-capable view is opened, rather than on the initial mission brief. The Three.js bundle remains sizable; catalogue thumbnails are separately downsampled (regenerate with `node scripts/prepare-thumbnails.mjs`, which requires ImageMagick). When WebGL is unavailable or a context is lost, the explorer switches to an interactive 2D view and offers a 3D retry. Camera refocusing respects the browser's reduced-motion preference. Favourites fall back to the current session and show a notice if browser storage is blocked; mission-library saves report storage failures separately. The solar timeline does not accumulate hidden-tab time.

## Available features

- WebGL scene with textured Sun, eight planets, Pluto, Ceres, the Moon and the four Galilean moons; generic procedural models of Haumea, Makemake, Eris, Eros and Halley; Earth day/night maps, cloud layer, ocean highlights and illustrative atmosphere; procedural Saturn rings and optional synthetic star field; Sun-directed planetary shading. Exposure is normalized for readability, not radiometrically accurate.
- Date, play/pause, reverse, speed and reset controls, drag/zoom/pan, click selection, overview, follow, orbital paths, labels and display settings. The default readable view exaggerates body sizes and compresses distances; focus normally isolates the selected world. “Show surrounding bodies” retains the surrounding system with the same compressed scales.
- **Physical-scale navigation** in Display Settings renders modeled centers in AU and spheres using approximate physical radii. Focus-relative coordinates are computed in double precision before rendering, with logarithmic depth buffering; smoothly refocus using the catalogue and zoom or pan across the system. At real scale most bodies are too small to click or see from a system overview, so labels and the catalogue aid navigation. Orbital positions remain approximations and some planet centers are system barycenters; labels, belt particles and ring appearance are illustrative; the catalogue sky is not aligned. Oort Cloud automatically switches to the separately scaled conceptual view. The atmosphere toggle controls the illustrative planetary halos and Earth cloud layer in both views. Unknown SBDB diameters produce no visible surface rather than an invented size. Saturn’s broad ring inner/outer radii are approximately scaled to Saturn; opacity and shape are illustrative. An approximate planet shadow falls on its rings in both views, while an approximate ring shadow falls on Saturn only in the readable view; neither is a measured optical-depth or precision eclipse model. Surface orientations, solar illumination and spherical shapes are approximate, especially for irregular bodies. Haumea uses an approximate equatorial radius; Makemake and Eris use half of NASA’s approximate diameters. Phobos, Deimos, Enceladus, Rhea and Iapetus use volume-equivalent spheres based on published axes. See [NASA Haumea](https://science.nasa.gov/dwarf-planets/haumea/), [Makemake](https://science.nasa.gov/dwarf-planets/makemake/), [Eris](https://science.nasa.gov/dwarf-planets/eris/) and the moon fact sheets below.
- Symbolic, procedural asteroid and Kuiper belt particles visible in overview: their radii are broadly illustrative, and the particles are **not** catalogue bodies or real individual positions. They can be toggled off. A separate conceptual Oort Cloud view depicts a hypothesized spherical shell with artificial particles, not observed objects or measured densities; the shell and inner system have independent scales. [NASA](https://science.nasa.gov/solar-system/oort-cloud/facts/) describes the cloud as extending roughly 5,000–100,000 AU, with an uncertain structure.
- Searchable local inventory with filtering, sorting, favourites and recent items; size comparison of planets, Pluto, Ceres, Eros, Halley and selected moons (a 4-pixel minimum means very small bodies are not exactly proportional). The Moon and four Galilean moons use approximate date-dependent satellite vectors; Pluto uses its approximate system-barycenter trajectory. The remaining named dwarf planets, Eros and Halley use offline osculating-element approximations; the remaining listed moons interpolate live Horizons tracks when available.
- **Additional moon tracks:** selecting Phobos, Deimos, Titan, Enceladus, Rhea, Iapetus, Triton or Charon requests 25 hourly Horizons parent-centered geometric position and velocity vectors spanning the selected UT day. Cubic Hermite interpolation animates between samples without extrapolation. Pause or use real-time speed to load a track; rapid playback suspends requests. When JPL is unavailable the parent is shown with an error, and retry is offered. The parent itself uses an approximate system-barycenter position (including Charon anchored to the Pluto-system barycenter rather than the Pluto center); visual sizes and distances are independently exaggerated in the readable view; the optional physical view retains physical scale.
- Live SBDB search by name/designation in NASA Data. A returned bound elliptical orbit with complete elements can be explored as a two-body approximation from its JPL solution epoch; its generic rock shape is procedural and is **not an observed image or shape model**. Hyperbolic, incomplete, or unavailable solutions are not rendered. Solar perturbations and uncertainty are not propagated, so the approximation may degrade substantially away from the solution epoch.
- On-demand Horizons vector comparison for the selected planet, Pluto, modeled moon, or offline minor body, at 12:00 UT on the simulation date, in the object's profile and NASA Data. The uncompressed model and the JPL result are compared in AU and km; no result is faked if the request fails.
- Five manual quality settings adjust resolution and the number of illustrative particles (sphere mesh detail also changes in the readable view); toggles control atmosphere/clouds, cinematic glow, the sky backdrop, orbit guides, labels, surrounding context and symbolic belts. High and above lazily load a 4,096 × 2,048 map for the focused Earth, Mars, Jupiter, Saturn or Moon only on capable GPUs; other presets and failed loads retain the smaller map. The previous detail map is released on focus changes. Cinematic view temporarily hides object labels for a cleaner composition and restores the label setting on exit. These presets are not yet an adaptive LOD system.
- **Cinematic view** (eye button beside the scene, Escape to exit) hides the surrounding panels and reframes the selected object; it keeps the current simulation, scale and interaction. A mobile portrait-aware framing keeps planets within the screen. Orbit guides can still be toggled. Neither this presentation view nor the lighting changes adds ephemeris accuracy.

## Phase 2: Milky Way and the solar neighborhood

Zoom out past the Solar System camera limit (wheel or pinch) to enter the solar neighborhood; the globe button is an accessible alternative. Zoom back into the Sun or use **SOLAR SYSTEM** to return. Select a catalogue star and zoom into it to open its system when one of the six curated planetary systems is available; other stars do not get invented planets. The handoffs switch renderers and scales, rather than performing a continuous physically scaled flight. The overview is an interactive, procedurally generated barred-spiral *illustration*, not a photograph, real star catalogue, fitted spiral-arm map, or a simulation of galactic dynamics. The density selector requests 200,000 or 1,200,000 artificial particles generated in a worker, starting from a 38,000-point preview. A frame-rate budget adjusts how many are drawn; the displayed count is the actual visible point budget, not a guarantee that every device can render the full target. These artificial particles have no individual astronomical counterparts and cannot be selected as real objects. The illustrative disk is about 100,000 light-years across; the Sun is placed 26,000 light-years from the center, in the plane, at an arbitrarily chosen azimuth. Neither the relative orientation nor exact shape, number and location of the arms should be treated as an observation. The detailed structure of the Galaxy remains uncertain. Decorative blue, rose and warm glowing knots are sampled from the synthetic particles and are not observed nebulae or a dust map. The particles fade as the camera approaches the local stars, avoiding a false impression of individually mapped galactic stars. The Galactic Center marker is not a physical-scale rendering of Sagittarius A*.

Select **Solar neighborhood** or a star in the searchable catalogue to navigate among **1,900 entries within 20 parsecs** of the Sun. An optional on-demand 20–50 pc extension adds 6,849 entries, for 8,749 loaded stars within 50 pc. This is a filtered, incomplete subset of the **HYG Stellar Database v4.0**, assembled by David Nash / Astronexus from the Hipparcos, Yale Bright Star and Gliese catalogues. It is not Gaia data and not a complete census. Search covers the currently loaded entries by name, HYG/HIP/HD identifier, Gliese or the supplied Bayer/Flamsteed designation. Results are paginated in distance order (50 per page); the optional leading spectral-class filter applies only to the list, not the 3D map or diagram. Each star's J2000 equatorial right ascension and declination are transformed using the standard IAU Galactic rotation and its catalogue distance converted from parsecs to light-years (1 pc = 3.261563777 ly). Relative positions use those static estimates; parallax uncertainties, proper motion, binary orbital motion, stellar sizes and light travel time are not modeled. Point colors are simplified from catalogue color index where available and not calibrated photometry; rendered sizes and brightnesses are symbolic (the HYG magnitude influences their display size). Close companions can overlap on screen. The solar-system and galaxy modes use separate scenes, not a continuous physical transition down to planetary scale. The Solar System timeline pauses while exploring the galaxy and resumes with its previous play/pause state on return.

## Scientific method and limitations

Planet positions use [NASA/JPL Table 1](https://ssd.jpl.nasa.gov/planets/approx_pos.html): J2000 elements and their secular rates, solving Kepler's equation in the heliocentric J2000 ecliptic frame. The table is only valid from **1800 through 2050**; the timeline is limited to that range. Earth uses the Earth–Moon barycenter, not Earth's center. The JavaScript UTC date is treated approximately as TDB in the model, introducing an additional timing offset. Orbit guides freeze fitted elements at a given year and are not exact future trajectories. The fitted model is not a numerical N-body integration and does not include full perturbations, light-time corrections, precession or a high-precision ephemeris. Rotations and tidal locking are approximate and are not registered to actual prime-meridian epochs. Earth and Jupiter system models anchor their satellites to the rendered planet, whose center uses the approximate planetary barycenter. Do not use this simulator for navigation or precision astronomy.

### Limited Horizons validation

On 2026-11-13, six geometric heliocentric J2000 ecliptic vectors were obtained from JPL Horizons DE441 for the Earth–Moon, Mars and Jupiter **system barycenters**, at JDTDB 2451545.0 and 2460677.0. Comparing against this model using the same numerical date as UTC yielded the following Euclidean vector differences (including the uncorrected UTC/TDB difference):

| System barycenter | 2000-01-01 12:00 | 2025-01-01 12:00 |
| --- | ---: | ---: |
| Earth–Moon | 2,006 km | 3,080 km |
| Mars | 8,193 km | 18,601 km |
| Jupiter | 1,149,745 km | 609,716 km |

The source query format is [Horizons API](https://ssd-api.jpl.nasa.gov/doc/horizons.html), with `CENTER=500@10`, `REF_PLANE=ECLIPTIC`, `OUT_UNITS=AU-D`, `VEC_TABLE=1`, `VEC_CORR=NONE` and commands `3`, `4`, `5`. These are sparse regression checks, **not comprehensive validation** and not guaranteed error bounds. The automated tests retain the reference vectors and broad tolerances. The live comparison endpoint uses Horizons UT and displays its retrieval date. Horizons uses UT1 before 1962, UTC afterward, and estimates future leap seconds.

Positions are calculated in JavaScript double precision. The default readable view uses nonlinear distance compression and separately exaggerated radii; the optional physical view uses a focus-relative origin, physical radii and uncompressed distances. This is not a precision ephemeris or a fully general hierarchical, adaptive-LOD universe engine. The atmosphere halos, cloud motion, belt particles, procedural star field, ring profile and approximated ring shadows are illustrative rather than measured current observations. Texture maps are not live images. Planetary measurements are rounded from [NASA's Planetary Fact Sheet](https://nssdc.gsfc.nasa.gov/planetary/factsheet/); gas/ice giant temperatures are representative upper-atmosphere values. Missing values are shown as unavailable. Static facts were consulted on 2026-11-13; moon counts are deliberately omitted because they change.

**Major remaining work:** further hardening of multiscale navigation and precision across extended distances; offline ephemerides for the live-track satellites; more accurately propagated asteroids and comets; observed detailed minor-body shapes; normal/displacement maps, physically based atmospheric scattering, ring shadows and higher-fidelity lighting; perturbations and precision ephemerides; adaptive rendering/geometry LOD; comprehensive object profiles; robust long-duration performance and leak testing; broad browser/device/accessibility QA; and validation across all bodies and dates. Phase 1 should not be marked complete until these gaps and the original project's broader requirements are addressed.

### Live-track satellite check

For the rapidly orbiting Phobos, a single comparison of cubic Hermite interpolation between Horizons 2026-11-13 00:00 and 01:00 UT state vectors against an independent 00:30 UT Horizons vector differed by approximately **9.95 km**. This is one spot check, not a general error bound or a precision claim. Sample timing follows Horizons UT (UT1 before 1962, UTC afterward, with future leap seconds estimated). Planetary centers and display geometry remain approximate.

### Offline dwarf planets, Eros and Halley

The [JPL Small-Body Database API](https://ssd-api.jpl.nasa.gov/doc/sbdb.html) supplied full-precision osculating heliocentric J2000 ecliptic elements for Ceres (solution 48), Haumea (132), Makemake (130), Eris (103) and Eros (659), retrieved 2026-11-13. For Halley, [Horizons](https://ssd.jpl.nasa.gov/horizons/) solution JPL#75 was queried for osculating elements at the same epoch. All are fixed at **JD 2461200.5 TDB (2026-06-09 00:00)** and propagated as unperturbed ellipses. Gravitational perturbations and cometary outgassing are not modeled; results may become very inaccurate away from that epoch. Displayed years from epoch are not an error estimate. UTC is approximated as TDB. Do not use these approximations for predictions or navigation.

At the element epoch, the vectors reproduced separately retrieved Horizons snapshots to within 4.1 km (Ceres), 0.2 km (Haumea, Makemake and Eris), 0.7 km (Eros), and under 1 meter (Halley). This is principally a check of element conversion, **not independent validation over time**. For Halley at 2025-01-01 12:00 TDB, the two-body result differed from Horizons by about 216,930 km; other dates and objects have not been systematically validated. The orbit guides are fixed ellipses. The shapes of Haumea, Makemake, Eris, Eros and Halley are illustrative, not measured shape models; Halley's activity and tail are not rendered. Ceres uses a Dawn mosaic. Physical entries are rounded from SBDB; missing data are not fabricated.

### Satellite and Pluto spot checks

Satellite vectors are calculated with [Astronomy Engine](https://github.com/cosinekitty/astronomy) (MIT), using its lunar and Galilean moon models; Pluto uses its Pluto-system trajectory. J2000 equatorial vectors are rotated to the J2000 ecliptic. Parent-relative satellite vectors were compared with Horizons at 2000-01-01 and 2025-01-01, 12:00 UT (Moon relative to Earth, Galilean moons relative to Jupiter; DE441 / jup365_merged). Approximate Euclidean differences in km:

| Body | 2000 | 2025 |
| --- | ---: | ---: |
| Moon | 10.7 | 10.8 |
| Io | 59.8 | 49.8 |
| Europa | 64.3 | 49.3 |
| Ganymede | 150.5 | 296.0 |
| Callisto | 155.8 | 538.2 |
| Pluto system barycenter, heliocentric | 9,722 | 129,727 |

These are only two spot checks, not guaranteed errors for other dates. Satellite paths are sampled predictions over one approximate orbital period, not exact closed orbits. The readable visualization applies independent scale changes; both views use approximate surface orientations and barycenter-based parent positions, so neither should be used to judge libration or precision eclipses.

## Architecture and verification

`src/orbits.js` contains planetary and small-body coordinate calculation; `src/satellites.js` contains Astronomy Engine satellite and Pluto adapters; `src/minorBodies.js` records the offline JPL osculating elements; `src/liveMoons.js` defines live-track moon display metadata and interpolation; `src/data.js` the local Solar System inventory; `src/galaxyModel.js`, `src/galaxyWorker.js`, `src/zoomBoundary.js`, `src/deepSky.js`, `src/GalaxyScene.jsx` and `src/GalaxyExplorer.jsx` the Milky Way, curated landmark and nearby-star view; `src/Scene.jsx` the readable Three.js renderer, `src/ScaleScene.jsx` the focus-relative physical renderer and `src/scaleModel.js` its physical radii; `src/ScienceTools.jsx` the JPL tools; `src/main.jsx` the UI; `server/app.js` the proxy and `server/index.js` its entry point. `npm test` checks galactic coordinate conversion, landmark data and catalogue invariants, orbit math, physical-scale conversions and coverage, selected Horizons planet, Pluto, satellite and minor-body snapshots, validation, cache and API failure handling with mocked upstreams; `npm run build` builds the app. Headless Chromium smoke tests exercised desktop and mobile interactions, with mocked SBDB/Horizons responses, including the live-track moon success and failure flows, physical mode focus transitions across inner planets, outer worlds and moons, Oort Cloud fallback, and a production-build smoke check. The sandbox server could not reach those external hosts, so live end-to-end proxy calls were not verified there. These tests do not replace hardware, long-duration or comprehensive ephemeris validation.

Codebase developed with Arena.ai. Scientific concept, project direction, ideas and development prompts created by a human developer.

### Local stellar connections

Selecting a HYG star shows the five closest stars among the **currently loaded** 20 pc or optional 50 pc subset, with clickable navigation and optional straight-line guides. Separation is calculated from static J2000 equatorial positions and catalog distances; it is not a trajectory or a binary-orbit model. HYG is incomplete and the Sun is excluded from these subsets, so these are not necessarily the actual nearest stars. Distance uncertainty, proper motion and parallax corrections are not propagated. The galaxy cinematic view hides the panels and can be exited via the button or Escape.

### Planetary systems (Phase 2, partial)

Six explicitly matched HYG stars (Proxima Centauri / HIP 70890, Ran / HIP 16537, Gl 876 / HIP 113020, Gl 581 / HIP 74995, Copernicus / HIP 43587, and Helvetios / HIP 113357) have an interactive system explorer. The mapping is curated, not an automatic name or positional match: see the [NASA ExEP star list](https://exoplanetarchive.ipac.caltech.edu/docs/2645_NASA_ExEP_Target_List_HWO_Documentation_2023.pdf), and system overviews at the [NASA Exoplanet Archive](https://exoplanetarchive.ipac.caltech.edu/). HIP identifiers and J2000 positions are regression-checked against HYG; proper motion and catalog differences prevent exact position agreement. **This is not a census:** the other HYG stars are not known to be planet-free, and candidate/confirmed classifications evolve.

The server attempts a live, host-allowlisted [NASA Exoplanet Archive TAP](https://exoplanetarchive.ipac.caltech.edu/docs/TAP/usingTAP.html) query of the **Planetary Systems** (`ps`) table with `default_flag=1` (the Archive's chosen literature solution per confirmed planet). The application displays its actual retrieval time and caches server responses for up to one hour. On network failure it falls back to the bundled **2026-11-13 snapshot**, with retry and explicit source selection; the snapshot can be stale. Neither the endpoint nor the data need a NASA API key. NASA/JPL outbound access is blocked in this development sandbox, so a real server-side archive connection was not verified here; mocked success and failure paths were tested. Empty live results do not trigger an unlabelled fallback.

The snapshot `public/data/exoplanet-snapshot.csv` was copied from the TAP response on 2026-11-13 and converted to `exoplanet-snapshot.json` by `python3 scripts/convert-exoplanet-snapshot.py`. The original measurement CSV came from the following query:

```sql
select pl_name,hostname,pl_orbper,pl_orbpererr1,pl_orbpererr2,pl_orbperlim,pl_orbsmax,pl_orbsmaxerr1,pl_orbsmaxerr2,pl_orbsmaxlim,pl_rade,pl_radeerr1,pl_radeerr2,pl_radelim,pl_bmasse,pl_bmasseerr1,pl_bmasseerr2,pl_bmasselim,pl_bmassprov,discoverymethod,disc_year,ra,dec,sy_dist from ps where default_flag=1 and hostname in ('Proxima Cen','eps Eri','55 Cnc','51 Peg','GJ 876','GJ 581') order by hostname,pl_orbper
```

The reference, solution type and controversy flag were retrieved separately on the same date into `public/data/exoplanet-references.json` using `select pl_name,hostname,pl_refname,pl_controv_flag,soltype` with the same host filter and default flag. The converter joins them by planet and host; independently retrieved defaults can change between queries. Live requests use the combined column list in `src/exoplanets.js`. A controversy flag of zero means only that the Archive does not flag it as controversial.

See the [NASA column definitions](https://exoplanetarchive.ipac.caltech.edu/docs/API_PS_columns.html) and linked host overview for primary literature, alternative solutions and methodology. Period is in days, semi-major axis in AU, mass in Earth masses, and radius in Earth radii. Errors are the quoted upper/lower uncertainties when supplied; limits use the archive's limit flags. `Msini` is **minimum mass**, not true mass. Uncertainties absent from a source are not zero; these literature-derived values can be model-dependent and are not all direct measurements. HYG and NASA distances are from different catalogues.

The Three.js view is an **illustration, not an ephemeris**: circular coplanar orbits, arbitrary initial phases, logarithmically compressed spacing, symbolic sizes/colors, and an artificial background star field. Perspective and top-view buttons are available. It uses listed periods only to animate elapsed schematic time, and draws only non-limit semi-major axes. It does not predict a planet's observed location or depict its surface. Rows without orbital sizes remain selectable in the list. Search covers host names and the saved planet names, not every current Archive alias. Stellar and planetary data are not a complete Phase 2 galaxy or a finished Phase 1 Solar System.

Cross-identification references for these selected hosts: [Proxima Centauri / HIP 70890](https://exoplanet.eu/catalog/proxima_centauri_b--4042/), [Ran / HIP 16537 and Copernicus / HIP 43587](https://exoplanetarchive.ipac.caltech.edu/docs/2645_NASA_ExEP_Target_List_HWO_Documentation_2023.pdf), [GJ 876 / HIP 113020](https://arxiv.org/html/1404.5335), [GJ 581 / HIP 74995](https://iopscience.iop.org/article/10.1088/2041-8205/729/2/L26), and [51 Peg / HIP 113357](https://www.openexoplanetcatalogue.com/planet/51%20Peg%20b/). These corroborate the curated identifiers; the selected NASA Archive rows, not those references' planet counts or parameter estimates, determine what is displayed.

### Gaia DR3: one million local catalogue sources

The galactic explorer offers an **optional**, separately labelled layer of exactly **1,000,000 distinct Gaia DR3 source IDs**. Turn on “Show observed local stars” in the galaxy catalogue; this downloads a 24 MB binary and prepares it in a worker. Search that layer by numeric Gaia DR3 source ID to inspect its approximate position, distance and available quantized photometry. The Gaia points are not individually clickable and do not imply known planets; the existing HYG list and its six curated planetary-system views remain separate. The renderer starts with 50,000 Gaia points and adapts its draw budget to the device; the entire million is loaded and searchable, but is not necessarily drawn at once. The Gaia layer fades out far from the Sun. The glow, colour ramp and point sizes are illustrative, not physical stellar radii or calibrated images.

**Important coverage:** this is *not* one million objects spread across the whole Milky Way. It is a selected, incomplete and biased local 100–500 pc sample around the Sun. Its source uses `parallax > 2 mas` and `parallax_over_error > 10`, excludes the Gaia Catalogue of Nearby Stars and sources with parallax above 10 mas, and estimates distance as inverse parallax. Inverse-parallax distances have uncertainties and selection biases; positions and photometry are quantized, missing photometry is possible, and individual uncertainties/proper motions are not included. The separately displayed galaxy spiral, diffuse emission and bar are schematic, not measured Galactic structure. The HYG and Gaia samples are not merged or cross-matched.

The source is [azuregroove/galaxie-data, Gaia 500 pc tiles](https://github.com/azuregroove/galaxie-data/tree/59fcf5d6cf3103f6d9a5ca91f4784bbd07d9c17d/gaia500), upstream revision `59fcf5d6cf3103f6d9a5ca91f4784bbd07d9c17d`, based on `gaiadr3.gaia_source`, retrieved by upstream from the ARI Gaia archive on 2026-10-03. We selected the first million records in upstream breadth-first node order (truncating the final node), decoded its quantized positions, kept the source IDs and quantized G and BP−RP bytes, and repacked them into a 24-byte-per-record binary. This selection and repacking is a further adaptation. `public/data/gaia-dr3-1m.json` documents the exact node counts, format and SHA-256. `python3 scripts/prepare-gaia.py` reproduces it using the GitHub CLI and the pinned source revision; use `--cache` and `--index` for cached tiles and index. GitHub authentication and network access are needed when fetching the source tiles.

### Rendering refinements

Textured planets, dwarf planets and mapped moons share improved sunlight/terminator and limb shading in both scale modes. The physical-scale view also has the same optional artistic atmospheric rims and static Earth cloud layer as the readable view, plus a procedural solar corona; its light calculations use the focus-relative Sun position. The Sun's corona and rays, particle glow profiles, exoplanet marker lighting and galaxy haze are artistic effects—not images of current conditions or measured stellar/planetary surfaces. Exoplanet planets and their generic procedural host-star surfaces remain symbolic, with unknown real appearances, sizes and orbital phases. Symbolic asteroid belts, Oort Cloud and background particles use soft sprites, and the existing quality controls still limit particle counts and resolution. None of these rendering changes improves the positional or ephemeris accuracy.

### Moving around

Use **+**, **−**, and **Reset view** beside each 3D scene to zoom or reframe the current selection. Scroll or pinch also zooms; dragging rotates. On a keyboard, `+` / `−` zoom when a text field or modal is not active, and Ctrl/⌘+K focuses the current catalogue search. The controls stop at the scene's zoom limits; they do not silently enter another renderer. Use **Explore the galaxy** in the Solar System, **Enter Solar System** in the local neighborhood, or **Explore planetary system** for one of the six supported hosts. Wheel/pinch boundary handoffs remain available; transitions switch scenes rather than representing continuous travel.

On mobile, the Objects menu provides all sections, including the database and comparison. The close button, outside backdrop, or Escape dismisses the drawer. Use **More details** on a profile to expand its information, then **Less details** to return to the scene. The database, comparison, science and NASA panels include section links; Escape closes them, and catalogue searches have a clear button. Exoplanet systems have their own zoom and reset controls as well as perspective and top views. Unsupported stars still have no planetary-system view; this does not mean they have no planets.

### Mission Design Lab

The app opens in **Mission Lab**; select **Explore the cosmos** to enter the Solar System, and return via Mission Lab in its navigation, the mobile Objects menu, or the galaxy header. Choose an objective and subsystems, inspect live mass, budget, power and communications margins and a preflight checklist, then operate a deterministic mission. Make decisions at three simulated events and review an interactive, keyboard-accessible monthly chart and data table, data-accounting diagram, flight log, full configuration and actionable feedback. Short NASA mission examples are linked for each science objective; they are context, not parameters or validation for the game. Iterate to compare score and cost against the previous design for the same objective, or download a text report. At each event, compare the model’s estimated return, loss and campaign score before deciding; the first event’s campaign forecast assumes the stated later response. Share a versioned link containing the component choices and campaign condition; recipients explicitly choose whether to load it over their saved design. Flight decisions and reports are not embedded, so matching a report also requires choosing the same responses. The current design is autosaved locally in the browser; the optional Design Library separately stores up to five named configurations in that browser. Loading and deleting a saved design require confirmation; the reset action clears the current design and comparison but not saved library entries. Flight decisions and completed reports are checkpointed locally after launch when browser storage is available; a matching, versioned checkpoint can be resumed or discarded after a reload. Reports are recalculated, and checkpoints are cleared by reset, a new flight, loading or changing a design, or iterating. Storage can be unavailable or cleared by the browser. Previous-design comparison is session-only. The report also compares the same design and decisions across the three fictional campaigns; this is a deterministic counterfactual, not a forecast or a set of independently chosen decisions.

This is a simplified educational trade model, not a validated mission engineering tool. Component parameters, costs, orbital sunlight/contact fractions, science targets and disruption events are illustrative. A two-body circular orbital period uses NASA's Earth mean radius and gravitational parameter from the [Earth Fact Sheet](https://nssdc.gsfc.nasa.gov/planetary/factsheet/earthfact.html); mission-design concepts are informed by NASA's [Design and Develop Science Missions](https://www.nasa.gov/wp-content/uploads/2025/04/250323-design-and-develop-science-mission.pdf), [Small Spacecraft Power](https://www.nasa.gov/wp-content/uploads/2025/02/3-soa-power-2024.pdf), and [Communications](https://www.nasa.gov/smallsat-institute/sst-soa/soa-communications/) resources. See the in-game methods for the scoring formula and omissions. The mission hero and science objective cards are AI-generated conceptual artwork. The assembly and orbit views use interactive procedural 3D spacecraft and a static NASA Blue Marble map on GPUs that support it (otherwise the Three.js example map). These are not flight imagery, engineering CAD, or trajectories; scale, camera framing, spacecraft shape, apparent motion, illumination and orbit path are illustrative. The conceptual spacecraft includes design-dependent panels, bus, instrument silhouettes and antenna, with procedural insulation and fittings. It can be dragged, tilted, rotated, zoomed and reset. The flight view offers orbit and spacecraft-following concept cameras; neither describes real pointing or ground coverage. Earth shading combines static day, night, cloud and specular visualization maps, not live observations. Orbit movement, trails and the optional skippable launch transition are artistic rather than propagated spacecraft trajectories. Motion respects reduced-motion settings and can be paused; rendering pauses when offscreen and resources are disposed on exit. Clouds are static illustrative textures, not current conditions. A schematic fallback and retry control are shown if WebGL is unavailable or its context is lost. In-flight decisions and their consequences are simplified game rules; see the in-game methods.
